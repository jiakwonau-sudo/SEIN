# 세인코퍼레이션 내부 관리 시스템

PRD v1.0과 원본 목업을 바탕으로 만든 웹 애플리케이션입니다. 파란색 상단 카테고리, 왼쪽 업무 메뉴, 표와 상세 모달 중심의 구성을 유지했습니다.

## 바로 실행

Node.js 24 이상이 필요합니다. 현재 구현·후속 변경·검수·운영 절차는 [최종 핸드오프](HANDOFF.md)를 먼저 확인하세요.

```powershell
npm ci
npm run build
npm start
```

`http://localhost:4173`에서 **로컬 업무 공간 열기**를 누릅니다. 설정이 없는 경우 로컬 모드로 실행하며, 실제 회사 계정이나 외부 고객에게 연결하지 않습니다. 새 로컬 데이터베이스는 업무 자료 없이 시작합니다. 로컬 관리자 계정 식별자에는 `example.test` 주소를 사용합니다.

- 저장 위치: `.local/sein.sqlite`, `.local/files/`
- 종료 후 다시 실행해도 등록·수정한 데이터와 파일을 유지합니다.
- 다른 컴퓨터에 공개되지 않도록 검토 모드는 `127.0.0.1`에만 바인딩합니다.
- 개발 중에는 `npm run dev`를 사용합니다.
- 원본 목업 HTML과 PRD는 보존했습니다. 앱 소스는 `src/`, API는 `server/`입니다.

## 구현된 업무

- 대시보드: 확정 거래의 원화 매입·판매·수익, 거래 건수, 단계 현황.
- 상품: 모델·수동 설비번호·물류 단계·매입 정보, 메모·태그·단계별 사진·원본 파일·영상 링크.
- 고객: 복수 담당자, 회사 송신 금지, 유효 이메일 일괄 복사.
- 영업: 복수 설비·동시 제안, 설비별 금액 배분, 판매 확정, 금액 정정·부분/전체 취소, 변경 이력.
- 견적: 국문/영문, KRW/USD/JPY, 부가세 3방식, 직접/자동 환율, 통화 환산, 버전별 실제 PDF와 스냅샷, 견적 선택 또는 견적 없는 판매 확정.
- 자료실: 재클릭 폴더 접기, 깊이별 아이콘/들여쓰기, 검색·형식·정렬, 50MB 업로드, 썸네일, 원본 다운로드, 100개/200MB ZIP, 일괄 이동/삭제, 30일 휴지통.
- 잠금: 대표 전용 숨김, 대상별 비밀번호, 상속·로그인 세션 해제, 서버 권한 검사.
- 회계: 자동 판매 내역, 연도별 자유 장부, 셀 참조 사칙연산, 행·열 편집, XLSX 입출력과 미지원 수식 변환 보고.
- 일정: 월간/목록, 반복·종료 조건·월말 보정·변경 범위, 앱 내 알림, 이메일 발송 작업 코드.
- 설정: 직원별 권한, 회사 정보, 확장 카테고리, 운영 연결 상태.
- 모바일/태블릿: 화면 폭으로 편집을 차단하지 않습니다. 계정별 업무 권한과 잠금은 PC와 동일하게 적용합니다. (2026-09-21 후속 결정)

**완성도와 미검증 범위는 `구현_및_검수현황.md`를 확인하세요. 현재 실행본은 운영 출시 승인을 받은 상태가 아닙니다.**

## 구조를 가볍게 유지한 기술 선택

- React + Vite, 일반 CSS, Lucide 아이콘. 대형 UI 프레임워크·상태관리 프레임워크를 추가하지 않았습니다.
- 하나의 Node/Express 서버에서 화면, 인증, 업무 API, 비공개 파일 제공을 처리합니다.
- 금액 계산과 반복·수식 규칙을 공통 모듈로 사용합니다. 수식에 `eval`/`Function`을 사용하지 않습니다.
- PDF/이미지/XLSX/ZIP 처리는 서버에서 수행합니다. 한글 글꼴과 문서 라이브러리는 브라우저 번들에 포함하지 않습니다.
- 운영 저장소는 Supabase Auth + PostgreSQL + Private Storage. 로컬 검토는 동일 업무 규칙 위에 SQLite 저장 어댑터를 사용합니다.
- 초기 4명 규모에서는 워크스페이스 JSONB와 버전 비교 저장으로 구조를 단순화했습니다. 판매 확정·일괄 작업은 통째로 성공하거나 실패합니다. 데이터 증가 시 조회 모델·서버 페이지네이션을 분리할 수 있습니다.
- 브라우저가 DB를 직접 읽지 않습니다. SQL RLS와 스토리지는 기본 차단하고 서버 전용 키를 API에서만 사용합니다.
- 서비스 계정·직원 이메일·발신 도메인·기존 도메인 값은 임의로 만들지 않았습니다.

## 운영용 Supabase 연결

1. 사용자 소유 Supabase 프로젝트에 `supabase/migrations/001_workspace.sql`을 실행합니다.
2. `.env.example`을 `.env`로 복사하고 `APP_MODE=supabase`, URL, 서버 전용 service role 키, `MASTER_EMAIL`, `APP_URL`을 설정합니다. 키는 Git에 올리지 않습니다.
3. Supabase Auth의 공개 가입을 끄고, 회사 도메인을 Site URL 및 허용 Redirect URL로 설정합니다. MASTER_EMAIL과 같은 이메일의 대표 계정을 안전하게 생성합니다.
4. 대표가 처음 로그인하면 마스터 프로필을 만듭니다. 이후 직원은 앱에서 초대합니다. 초대·비밀번호 재설정 링크의 비밀번호 입력은 사용자가 직접 수행합니다.
5. HTTPS가 있는 Node 24 호스팅에 `npm ci && npm run build` 후 `NODE_ENV=production npm start`로 배포합니다. 검토 모드를 운영 환경으로 올리면 시작을 거부합니다.
6. 일정 알림에는 `RESEND_API_KEY`, 인증한 `MAIL_FROM`, `CRON_SECRET`을 설정하고 관리형 스케줄러에서 1분마다 `POST /api/cron`을 호출합니다. 인증 헤더는 `Authorization: Bearer <CRON_SECRET>`입니다. 별도의 상품 단체 메일은 [Microsoft 365 연결 안내](MICROSOFT365_SETUP.md)에 따라 연결합니다. 검토용 모드는 고객 메일을 보내지 않습니다.
7. 별도 비공개 백업 저장소를 `BACKUP_DIR`로 연결하고 일일 `npm run backup`을 설정합니다. 파일과 DB를 각각 포함하며 최신 7개 날짜 백업을 보관합니다.
8. 실제 4계정, 도메인, 메일 수신, 상속 잠금, 복구를 운영 환경에서 검수합니다.

한 개 서버 인스턴스를 기준으로 합니다. 로그인 세션은 서버 메모리에 두므로 재시작하면 재로그인해야 합니다. 수평 확장 전에는 공유 세션·예약 작업 잠금 설계가 필요합니다. 실제 월 요금은 호스팅/메일/백업 계정 선택과 사용량을 확인해 확정합니다.

## 검증·백업

```powershell
npm test
npm run build
npm run backup
node scripts/verify-backup.mjs backups/YYYY-MM-DD_timestamp_id
node scripts/restore-local.mjs backups/YYYY-MM-DD_timestamp_id test-results/restore-new
```

복구 명령은 **존재하지 않는 새 디렉터리**만 받습니다. 기존 업무 데이터를 덮어쓰지 않습니다. Supabase 운영 복구는 별도 프로젝트에서 먼저 리허설해야 합니다. 백업에는 민감한 데이터가 포함되므로 공개 저장소나 브라우저 다운로드로 제공하지 않습니다.

## 2026-09-23 점검 후 개선

- 변경 없는 재조회는 짧은 응답을 반환하고, 저장 후에는 달라진 자료 종류만 전달합니다. 최초 조회는 전체 권한 필터링 자료를 받습니다.
- 메일은 계정별 서버 임시저장과 다른 창의 편집 충돌 확인을 지원합니다. 오류가 표시되면 내용을 복사해 두고 다시 열어 주세요.
- 태그 메모와 메일 고객사 목록은 40개씩 표시합니다. 상품·고객사·자료실 검색 조건은 계정·화면·카테고리별로 현재 탭에 보관하고 로그아웃 시 지웁니다.
- 예상 견적 합계는 진행 중 영업별 최신 버전의 원화 공급가입니다. 확정 매출은 판매 확정 내역을 기준으로 확인합니다.
- 백업은 `.incomplete-` 폴더에서 파일 참조·해시 검증 후 고유 완료 폴더로 전환합니다. 실패 폴더는 원인 확인용으로 남으며 정상 백업을 덮어쓰지 않습니다. 최신 7개 백업 날짜의 완료본을 보관합니다.
- 상세 구현 범위와 남은 운영 검수는 [점검 개선 결과](점검_개선결과_2026-09-23.md)를 참고하세요.
